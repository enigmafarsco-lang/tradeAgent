# نقشه‌ی راه و نسبت با `trade-mcp`

## ۱) پروژه‌ی قبلی چه بود

[`trade-mcp`](https://github.com/enigmafarsco-lang/trade-mcp) یک **سرور MCP** برای
MetaTrader 5 است که روی لینوکس بومی اجرا می‌شود و از طریق یک اکسپرت MQL5 (پل فایلی
یا سوکت) به ترمینال وصل می‌شود. تمرکزش روی **ابزار مشورتی** است:

* ۱۸ ابزار MCP: حساب، نماد، کندل، تحلیل چند تایم‌فریمی، ریسک/حجم، پیشنهاد سفارش،
  ژورنال SQLite، ایجنت‌های مقیدشده.
* جریان دو مرحله‌ای `propose_order` → تأیید انسان → `confirm_proposal`؛
  `ALLOW_TRADING=false` پیش‌فرض.
* کنسول محلی، بک‌اند mock، تست‌های آفلاین.

یعنی: «مدل پیشنهاد می‌دهد، انسان تأیید می‌کند». خوب و امن، ولی **خودگردان نیست** و
روی داده‌ی تیک ثانیه‌ای کار نمی‌کند.

## ۲) این پروژه چه اضافه می‌کند

| محور | `trade-mcp` | `tradeAgent` (این ریپو) |
|---|---|---|
| محرک | درخواست مدل/انسان | تایمر ۵ دقیقه‌ای |
| داده | کندل تایم‌فریم (M1+) | **تیک ۲۴ ساعته** از همه‌ی نمادهای ۲۴h |
| تصمیم | ابزار در اختیار مدل | استراتژی قطعی + نردبان سازگاری + LLM مقید |
| اجرا | پیشنهاد → تأیید → سفارش | **فقط کاغذی**، بدون مسیر سفارش |
| خروجی | پاسخ ابزار/کنسول | گزارش گیت هر ۵ دقیقه (قابل خواندن توسط ایجنت) |
| وابستگی | `mcp` | فقط کتابخانه‌ی استاندارد پایتون |

این دو مکمل‌اند، نه رقیب: همین ترمینال و همین پوشه‌ی `MQL5/Files` می‌تواند بعداً
هر دو را سرو کند.

## ۳) چرا اول کاغذی

1. **بازخورد سریع و بی‌هزینه:** می‌شود ۲۴ ساعت داده‌ی واقعی را در چند دقیقه
   شبیه‌سازی کرد، بدون ریسک حساب.
2. **کالیبراسیون هزینه:** مدل پرکردن (اسپرد + اسلیپیج + کمیسیون) را با اسپرد واقعی
   بروکر باید سنجید؛ اولین منبع ضرر در استراتژی‌های ثانیه‌ای همین است.
3. **حسابرسی:** هر تغییر سیاست با قبل/بعد و دلیل ذخیره می‌شود؛ قبل از پول واقعی
   باید بدانیم نردبان واقعاً کمک می‌کند یا فقط معامله را کم می‌کند.

## ۴) فازها

**P0 — پایه (همین حالا کامل شد)**

- [x] اکسپرت ضبط تیک + کشف خودکار نمادهای ۲۴ ساعته
- [x] خواندن افزایشی، کندل ۱ ثانیه، ژورنال SQLite
- [x] ویژگی‌ها/استراتژی‌ها/موتور کاغذی با کف هزینه
- [x] نردبان سازگاری + مشاور Gemini/Ollama با گارد
- [x] گزارش فارسی + انتشار گیت + systemd + تست آفلاین و CI

**P1 — اعتبارسنجی روی داده‌ی واقعی (هفته‌ی اول)**

- [ ] اجرای پیوسته و جمع‌آوری ۲۴–۷۲ ساعت تیک
- [ ] بررسی: نرخ تیک/ثانیه، اسپرد واقعی، فاصله‌ی زمانی تیک‌ها
- [ ] تنظیم `spread/slippage/commission` بر اساس همان داده
- [ ] مقایسه‌ی سه استراتژی پایه در گزارش روزانه

**P2 — بک‌تست و انتخاب (هفته‌ی دوم)**

- [ ] بازپخش آرشیو تیک با همان موتور کاغذی (بدون تغییر کد مسیر تصمیم)
- [ ] تقسیم train/test زمانی؛ ارزیابی نردبان در برابر سیاست ثابت
- [ ] معیارها: انتظار ریاضی به R، حداکثر دراوداون، تعداد معامله، حساسیت به اسپرد
- [ ] حذف/جایگزینی استراتژی‌های ضعیف

**P3 — تصمیم درباره‌ی اجرای واقعی**

- [ ] فقط اگر P2 مثبت و پایدار بود: اتصال به `trade_mcp.execution` برای ارسال
      سفارش **با تأیید انسانی دو مرحله‌ای** (هیچ اجرای کاملاً خودکار در گیت نباشد)
- [ ] سقف ریسک سخت در سطح سرور (نه در مدل): ماکس لات، ماکس ریسک، ماکس پوزیشن
- [ ] اجرای آزمایشی روی حساب دمو، سپس حساب کوچک واقعی

**P4 — اختیاری**

- [ ] داشبورد وب سبک (فقط خواندنی) برای اکوییتی/پوزیشن‌ها
- [ ] پشتیبانی چند ترمینال/چند حساب
- [ ] هشدار تلگرام/ایمیل از گزارش چرخه

## ۵) تصمیم‌هایی که باید تو بگیری

1. **سیستم‌عامل این کامپیوتر** (اوبونتو؟ دبیان؟ مک؟ ویندوز+WSL؟) — مسیر نصب
   Wine و مسیر `MQL5/Files` به آن بستگی دارد.
2. **بروکر/سرور MT5** و نام دقیق نمادها (`BTCUSD`، `BTCUSDm`، `BTCUSD.a` …) و
   اینکه حساب دمو داری یا نه.
3. **مدل:** Gemini رایگان (کلید می‌خواهد، سهمیه دارد) یا Ollama محلی (رم/VRAM
   می‌خواهد؛ ۷B حدود ۸GB). هر دو پشتیبانی می‌شوند.
4. **گزارش‌ها** در همین ریپوی `tradeAgent` (شاخه‌ی `reports`) یا ریپوی جدا/خصوصی؟

## ۶) کارهایی که عمداً در این نسخه نیست

* اجرای خودکار سفارش واقعی (نه در کد، نه در پیکربندی)
* وعده‌ی سود؛ این یک چارچوب پژوهشی/آزمایشی است، نه سیگنال‌فروشی
* معامله‌ی سهام/شاخص‌های سشن‌دار (تمرکز روی ۲۴ ساعته‌ها)
* یادگیری عمیق روی تیک (Kronos و مشابه) — بعد از P2 و فقط اگر داده کافی بود
