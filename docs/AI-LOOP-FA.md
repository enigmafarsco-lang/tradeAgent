# چرخه‌ی ۵ دقیقه‌ای — چه اتفاقی می‌افتد و چرا

```
زمان ──► tik‌های تازه (CSV) ──► کندل ۱ ثانیه ──► SQLite
                                              │
                                    (آخرین ۳۰۰ ثانیه + گرم‌کردن ۲۴۰۰ کندل)
                                              ▼
                                        ویژگی‌ها ──► استراتژی فعال
                                              │
                                              ▼
                                   ورود/خروج کاغذی + هزینه‌ها
                                              │
                        ┌─────────────────────┴─────────────────────┐
                        ▼                                           ▼
            نردبان سازگاری (قطعی)                       مشاور LLM (اختیاری)
             ۲ ضرر → تغییر روش                        پیشنهاد JSON + گارد
                        └─────────────────────┬─────────────────────┘
                                              ▼
                              سیاست چرخه‌ی بعد + گزارش + git push
```

## ۱) خواندن داده

* منبع پیش‌فرض: `data.harvester_dir` (پوشه‌ی اکسپرت).
* نمادها: `data.symbols`؛ خالی یعنی خودکار از `symbols.json`.
* فقط بایت‌های تازه‌ی هر فایل خوانده می‌شود؛ `offset` در `var/ingest_state.json`.
* تیک‌ها روی مرز ثانیه به کندل OHLC (mid) تبدیل می‌شوند و در جدول `bars` ذخیره
  می‌شوند (ایندکس روی `(symbol, t)`، درج تکراری نادیده).
* اگر داده‌ی یک نماد از `data.stale_after_s` (۱۸۰ ثانیه) قدیمی‌تر باشد در گزارش
  «کهنه» علامت می‌خورد و در هشدارها می‌آید. سیستم با داده‌ی کهنه **معامله نمی‌کند**
  به‌خاطر نبود کندل تازه (چون کندلی برای پردازش نیست) — ولی هشدار می‌دهد.

## ۲) ویژگی‌ها (`features.py`)

همه از داده‌ی گذشته و در بسته‌شدن کندل جاری؛ هیچ‌جا `bars[i+1]` خوانده نمی‌شود
(تست `test_features_finite_and_no_lookahead`).

| ویژگی | معنی |
|---|---|
| `ret_60_bps` | بازده ۶۰ ثانیه‌ی گذشته (پایه‌ی نقطه) |
| `vol_60_bps` / `vol_300_bps` | نوسان تحقق‌یافته (انحراف معیار بازده ۱ ثانیه × √n) |
| `atr_bps` | میانگین دامنه‌ی ۵ بلوک ۶۰ ثانیه‌ای (ATR چنددقیقه‌ای) |
| `z` | z-score قیمت نسبت به ۳۰۰ ثانیه |
| `hi_300` / `lo_300` | کانال ۳۰۰ ثانیه‌ای **بدون** کندل جاری |
| `spread_bps` | میانگین اسپرد ۶۰ ثانیه |
| `tick_rate` | میانگین تیک در ثانیه |
| `slope_300_bps` | شیب رگرسیون ۳۰۰ ثانیه |

نکته‌ی مهم: `atr_bps` روی دامنه‌ی ۱ ثانیه حساب **نمی‌شود**. اگر استاپ از نویز
یک‌ثانیه‌ای کوچک‌تر باشد، هر معامله فوراً استاپ می‌خورد و سیستم به‌جای معامله
فقط کارمزد می‌سازد. برای همین ATR بلوکی + کف هزینه (۳× اسپرد) اعمال می‌شود.

## ۳) استراتژی‌ها (`strategy.py`)

| variant | ورود | رژیم مناسب |
|---|---|---|
| `momentum` | شکست کانال ۳۰۰s + تکانه‌ی ۶۰s ≥ max(`min_edge_bps`, `breakout_k`×vol) | رونددار |
| `meanrev` | \|z\| ≥ `z_entry` و `vol_300 ≤ max_vol_bps` | آرام و بازگشتی |
| `scalp` | تکانه‌ی ۶۰s ≥ آستانه، هدف کوچک و نگهداری کوتاه، فقط اسپرد نازک | پرتیک، اسپرد کم |

هر سه اول فیلتر اسپرد (`spread_bps ≤ max_spread_bps`) دارند. خروجی هر استراتژی
یک `Intent` است: جهت، فاصله‌ی SL به bp، فاصله‌ی TP به bp، حداکثر زمان نگهداری.

## ۴) موتور کاغذی (`paper.py`)

* **پرکردن**: در بسته‌شدن کندل سیگنال، با قیمت همان بسته‌شدن + نیم‌اسپرد + اسلیپیج
  (`paper.slippage_bps`). هیچ نگاه به آینده.
* **حجم**: ریسک `paper.risk_per_trade_pct` درصد از بالانس × `risk_scale` سیاست؛
  notional از فاصله‌ی استاپ محاسبه و به `paper.max_notional_multiple` محدود می‌شود.
* **خروج**: اگر در یک کندل هم SL و هم TP لمس شوند، **SL** فرض می‌شود
  (محافظه‌کارانه). خروج زمانی هم هست (`hold_s`).
* **هزینه**: کمیسیون دو طرف (`paper.commission_bps`) + اسپرد/اسلیپیج در قیمت.
* **قفل‌ها**: حداکثر پوزیشن باز، کول‌داون هر نماد، سقف افت روزانه
  (`paper.daily_loss_stop_pct`) که تا پایان روز ورود جدید را می‌بندد.
* **ژورنال**: `bars`, `positions`, `trades`, `policies`, `decisions`, `cycles`,
  `meta` در یک فایل SQLite (`var/paper.sqlite3`).

حساب‌داری: `equity = balance + Σ unrealized`، `peak_equity` برای دراوداون،
استریک برد/باخت در `meta` نگه داشته می‌شود تا بین چرخه‌ها و ری‌استارت‌ها بماند.

## ۵) نردبان سازگاری (`policy.py`)

هدف: «اگر چند ضرر داد، نحوه‌ی باز کردن و بستن معامله را عوض کن» — ولی به‌شکلی
که قابل حسابرسی و برگشت باشد.

* پس از `policy.adapt_after_losses` ضرر پشت‌سرهم، سطح (`level`) یک پله بالا می‌رود.
* هر سطح، تبدیل مشخصی روی پارامترها دارد (جدول در README).
* حداقل `policy.adapt_cooldown_cycles` چرخه بین دو تغییر فاصله است.
* `policy.recover_after_wins` برد پشت‌سرهم یک پله عقب می‌آورد؛ سطح ۰ = پایه.
* سیاست از روی `level` **از صفر بازسازی** می‌شود، پس هرگز به وضعیت خراب/غیرقابل
  بازتولید نمی‌رسد و همه‌ی پارامترها در `PARAM_BOUNDS` گیر می‌کنند.
* هر تغییر به‌صورت `Decision` (قبل/بعد/دلیل) در گزارش و جدول `decisions` ثبت می‌شود.

## ۶) مشاور LLM (`llm.py`)

* `llm.provider`: `gemini` (کلید در `GEMINI_API_KEY`)، `ollama` (محلی)، یا `none`.
* حداکثر هر `llm.every_cycles` چرخه یک بار، و سقف `llm.max_calls_per_hour`.
* ورودی: سیاست فعلی، آمار، استریک، معاملات اخیر، وضعیت بازار چند نماد.
* خروجی: JSON با `variant`, `params`, `reason`, `confidence`, `notes`.
* اعتبارسنج (`policy.validate_proposal`):
  * `variant` فقط از سه‌گانه‌ی مجاز؛
  * هر پارامتر حداکثر ±۲۰٪ و داخل بازه‌ی مجاز؛
  * کلید ناشناخته دور ریخته می‌شود (`risk_scale`, `risk_per_trade_pct` از این
    مسیر قابل تغییر نیستند)؛
  * `confidence < 0.4` یا «هیچ تغییری» → رد.
* خطای شبکه/سهمیه/JSON → ثبت در گزارش، ادامه با سیاست قطعی. **هیچ‌وقت** چرخه
  به‌خاطر مدل نمی‌شکند.

## ۷) گزارش و انتشار

گزارش Markdown با ۸ بخش (خلاصه، معاملات، پوزیشن‌ها، سیاست و تغییرات، کیفیت داده،
مدل، هشدارها، چک‌لیست ایجنت) + یک خط JSON فشرده در `cycles.jsonl`. انتشار در
کلون جدا (`var/publish`) روی شاخه‌ی `reports` انجام می‌شود؛ ریپوی کد دست‌نخورده
می‌ماند. جزئیات: [PUBLISH-FA.md](PUBLISH-FA.md).

## محدودیت‌های آگاهانه این نسخه

1. **کاغذی است.** هیچ مسیر `OrderSend` وجود ندارد؛ نه کلید بروکر، نه اهرم واقعی.
   پرکردن سفارش با مدل ساده (اسپرد + اسلیپیج) شبیه‌سازی می‌شود، نه با دفتر سفارش.
2. **داده‌ی تیک به کیفیت فید بروکر وابسته است.** اسپرد واقعی در ساعات کم‌عمق
   بازار بیشتر از میانگین است؛ کف هزینه این را تا حدی جبران می‌کند.
3. **سوگیری انتخاب استراتژی وجود دارد** اگر روی همان داده‌ای که سیاست را تغییر
   می‌دهی، نتیجه را قضاوت کنی. قدم بعدی: بک‌تست آرشیو تیک + تقسیم train/test.
4. **نردبان قطعی است، نه یادگیری ماشین.** عمداً: باید بتوانی بگویی چرا سیستم
   رفتارش را عوض کرد. LLM هم فقط داخل همین قفس پیشنهاد می‌دهد.
5. **تک‌ترمینال.** این نسخه یک ترمینال/یک پوشه‌ی داده را می‌بیند.
